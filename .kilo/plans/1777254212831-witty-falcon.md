# Twenty CRM Features Integration Plan - Enhanced Pipeline Deals

## Overview
Integrate 86+ advanced features from Twenty CRM plus GTM Prompt Library Analytics system into the existing Enhanced Pipeline Deals application. This comprehensive plan includes pipeline views, deal management, analytics, automation, AI enhancements, API integrations, and now advanced prompt analytics for tracking AI performance, usage metrics, revenue attribution, and A/B testing within the CRM application.

## Technical Implementation Strategy

### Architecture Approach
- **Extend Existing Components**: Modify current pipeline views rather than rebuild
- **Modular Design**: Each feature as independent modules
- **Backward Compatibility**: Ensure existing functionality remains intact
- **Progressive Enhancement**: Features can be enabled/disabled via feature flags

### Key Technical Decisions
1. **State Management**: Extend Zustand stores for new features
2. **Database Schema**: Add new tables for templates, workflows, custom columns
3. **API Design**: RESTful endpoints for new functionality
4. **UI Framework**: Leverage existing Tailwind CSS and Lucide icons
5. **AI Integration**: Extend current GPT-5.2 services for new predictions

### Database Schema Extensions
```sql
-- Custom pipeline columns
CREATE TABLE custom_pipeline_columns (
  id UUID PRIMARY KEY,
  tenant_id UUID REFERENCES tenants(id),
  name TEXT NOT NULL,
  position INTEGER,
  config JSONB
);

-- Deal templates
CREATE TABLE deal_templates (
  id UUID PRIMARY KEY,
  name TEXT NOT NULL,
  description TEXT,
  template_data JSONB,
  is_public BOOLEAN DEFAULT false
);

-- Deal workflows
CREATE TABLE deal_workflows (
  id UUID PRIMARY KEY,
  name TEXT NOT NULL,
  stages JSONB,
  triggers JSONB,
  is_active BOOLEAN DEFAULT true
);

-- Deal health scores
ALTER TABLE deals ADD COLUMN health_score INTEGER CHECK (health_score >= 0 AND health_score <= 100);
ALTER TABLE deals ADD COLUMN win_probability DECIMAL(5,2);

-- GTM Prompt Library Analytics Tables
CREATE TABLE prompt_performance_metrics (
  id UUID PRIMARY KEY,
  user_id UUID NOT NULL,
  prompt_id TEXT NOT NULL,
  response_quality_score DECIMAL(3,2),
  response_time_ms INTEGER,
  token_usage INTEGER,
  cost_usd DECIMAL(8,6),
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE prompt_responses (
  id UUID PRIMARY KEY,
  user_id UUID NOT NULL,
  prompt_id TEXT NOT NULL,
  response_text TEXT,
  response_metadata JSONB,
  user_rating INTEGER CHECK (user_rating >= 1 AND user_rating <= 5),
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE prompt_ab_tests (
  id UUID PRIMARY KEY,
  user_id UUID NOT NULL,
  name TEXT NOT NULL,
  description TEXT,
  prompt_variants JSONB NOT NULL,
  status TEXT DEFAULT 'active',
  start_date TIMESTAMPTZ DEFAULT NOW(),
  end_date TIMESTAMPTZ,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE prompt_generation_logs (
  id UUID PRIMARY KEY,
  user_id UUID NOT NULL,
  prompt_id TEXT NOT NULL,
  generation_cost_usd DECIMAL(8,6),
  tokens_used INTEGER,
  model_used TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Row Level Security policies for GTM analytics
ALTER TABLE prompt_performance_metrics ENABLE ROW LEVEL SECURITY;
ALTER TABLE prompt_responses ENABLE ROW LEVEL SECURITY;
ALTER TABLE prompt_ab_tests ENABLE ROW LEVEL SECURITY;
ALTER TABLE prompt_generation_logs ENABLE ROW LEVEL SECURITY;

-- RLS policies (user can only access their own data)
CREATE POLICY "Users can access own performance metrics" ON prompt_performance_metrics
  FOR ALL USING (auth.uid() = user_id);

CREATE POLICY "Users can access own responses" ON prompt_responses
  FOR ALL USING (auth.uid() = user_id);

CREATE POLICY "Users can access own AB tests" ON prompt_ab_tests
  FOR ALL USING (auth.uid() = user_id);

CREATE POLICY "Users can access own generation logs" ON prompt_generation_logs
  FOR ALL USING (auth.uid() = user_id);
```
